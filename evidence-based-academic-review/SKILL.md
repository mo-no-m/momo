# 循证式学术综述写作 · v1.7

## 启动入口

- **仅有研究方向**：先读取 `references/literature-discovery.md`，分析现状、科学问题与争议，检索并推荐15–20篇代表性文献（按任务调整），提供研究贡献、局限、论证用途、DOI和核查深度。先交付文献推荐及候选主线，待用户确认后设计正式框架，再提交框架供用户审核；框架未经明确确认不得撰写正文。
- **拟写综述，已有题目或文献**：先核查现有证据，识别缺口，必要时补充文献，再设计论证主线和章节。按用户指定阶段开展工作，遵守相应审核节点。
- **只审已有稿件、核查引用或配图**：按 `references/evidence-audit.md` 审查论证和引用，或按下文流程配图。此类独立任务直接交付所需结果。用户授权改写既有稿件时，按所要求的范围修订，并沿用此前已约定的审核节点。
- 文献推荐标准、影响力指标、排序及输出格式参照 `references/literature-discovery.md`。没有联网或来源无法访问时，明确披露，不捏造文献或指标。

## 目标与原则

形成一篇有明确科学问题、证据链、分观点及总观点的综述，而非论文摘要拼接。默认中文学术写作，遵循用户给定的题目、篇幅、学科、格式和素材范围。课程论文默认可按约3000字规划；其他任务按用户要求。撰写综述须逐节协作，每一节需用户确认后才继续；仅在用户明确要求本次取消指定确认环节时才可例外，“写全文”仍走审核流程。对于系统综述、Meta分析等另有规范的任务，不把叙述性综述流程冒充系统综述。

优先级：事实准确与安全 > 证据对应 > 论证逻辑 > 文风 > 字数及格式。不得为保留论点、编号或凑字而牺牲事实。只提炼可公开解释的研究结论、证据类型与局限；生命科学任务遵守适用生物安全规范，不将文献综述转换为高风险生物工程操作、设计或优化指南，不绕过访问、安全或版权限制。

## 综述撰写的用户审核节点

1. **框架审核**：提交题目、核心科学问题、暂定总观点、章节标题及顺序、各节论证目标、核心参考文献、分观点、衔接关系与预计篇幅。明确询问“这个框架是否需要修改？确认后我再开始第一节。”结束本轮，不提前撰写第一节或其他正文。若用户提出修改，先调整并再次提交审核；只有用户明确确认框架（或已明确批准的现成框架）才进入写作。
2. **逐节循证写作与确认**：每轮只撰写当前一节。先核查该节证据，再交付该节完整正文、紧凑的关键事实—文献对应表、参考文献、证据边界及未核实项。写完必须明确询问“这一节的论证、内容或语言是否需要修改？确认后我再写下一节。”结束本轮，不提前输出下一节正文。用户反馈后完成修订并再次请求确认，直至明确通过；不得将沉默、仅提出修改意见或通用任务目标视为确认。“可以”“通过”“继续下一节”等在针对审核的回复中可视为明确通过。
3. **维护进度**：同步维护逐段证据账本，记录引用位置、原文证据和实际访问来源；区分未开始、待审核、待修订、已确认；记录已确认框架与各节版本、证据核查状态及未决问题。继续时从第一个尚未获批的节点开始，不重写已确认内容；若新证据导致实质性变更，说明原因并将受影响的框架或章节重新提交确认。用户明确确认不代替学术证据核查。
4. **收束与定稿**：所有主体章节通过后，依次撰写总结与展望、引言、摘要与关键词；分阶段交付且每个新写章节仍需确认。全部通过后才全文统稿，实质性改动需说明并提交审核。仅当用户明确要求本次跳过某个审核节点时才可按该指令调整，披露跳过项；不自动放宽后续节点。

## 工作流程

1. **确定问题**：获取题目、核心问题、受众、篇幅、文献时间区间、引用规范及已有素材。已知信息不重复询问。优先分析用户给的范例的组织和论证方式，不照搬原文。给出一句可检验的主线和暂定总观点；观点应允许证据修正。
2. **证据先行**：检索并核对文献，建立文献库及证据账本。优先相关性强的原始研究、可靠综述和指南；经典文献可明确作为例外。明确区分全文、摘要、索引和未获取证据。对于检索、推荐与核查细则，读 `references/literature-discovery.md` 和 `references/evidence-audit.md`。不能联网时说明，不宣称已检索。不能读取来源时请用户提供必要材料或保留待核查，不编造。
3. **布局并提交框架审核**：为每节确定问题、主要证据、比较或局限、暂定分观点、衔接下一节的科学逻辑和篇幅。标明各节之间依赖的证据及未验证的环节；可按机制、证据类型、应用或争议组织。参考 `references/style-and-delivery.md` 检查各节能否共同回答总问题。总观点随证据修正。完成框架后停下来让用户审核；确认前不得进入第4步。
4. **逐节循证写作、核查与确认**：采用“科学问题 → 文献方法/证据类型 → 研究结果 → 比较与局限 → 分观点”的可变结构。正文用连贯段落而非表格罗列；每节只讨论与其问题直接相关的证据。每节交付正文、关键事实与文献对应表、参考文献及未核实项。不得把研究设想、工具建立、机制证据和临床获益混为一谈。核查与修订同步进行。每次只写一节，交付后询问是否需要修改并结束本轮；修改后再次确认，用户明确通过后才开始下一节。
5. **吸收外部反馈**：若用户提供其他模型、审稿人、导师的意见，逐项区分采纳、部分采纳、不采纳、待证实，说明依据；事实争议回到原始来源，不因另一模型声称已检索就视为已独立核实。优先修正实质问题；不机械照搬修改，不为了形式加注无关内容。保留用户已经认可的结构与段落，除非证据或逻辑要求修改。
6. **总结与展望**：仅在全部主体章节获用户确认后进行。提炼各节分观点及其共性条件、证据缺口、未来需要解决的科学问题。提出与证据强度相称的总观点。避免逐节复述、空泛拔高及无依据的前景判断。
7. **后写前言**：默认正文与结论完成后写引言、摘要、关键词。引言以研究背景和未解决问题切入，定义服务于论述，再说明范围与目的；摘要概括问题、证据范围、主要认识、局限及总观点，无新数据，通常不引文献；关键词3–6个，按学科或期刊要求。用户明确不同顺序时遵从。
8. **全文统稿**：仅在所有章节及前置内容得到确认后开展。参照 `references/style-and-delivery.md` 检查自然过渡、段落功能、逻辑递进、术语、证据层次及重复句。尽量控制篇幅但不为了均分字数添加无关细节。顺序编码制按全文首次出现位置统一重编号；保留原编号仅当客观符合规则。最后检查所有文中引用与文末条目一一对应，并记录仍未确定的来源、指标及更正事项。将证据账本与最终段落及引用编号重新对齐，不能直接使用早期稿件的旧编号。
9. **交付**：提供独立、完整、可编辑的正式综述文件，仅包含题目、摘要、关键词、引言、正文、总结与展望及按指定规范著录的参考文献（经用户确认的学术图表及图注属于正文内容）。保留正常文内引文编号；默认不额外添加可点击文献链接、核查表、原文对照、审校记录、写作说明、进度或未决事项。核查和链接集中放在独立证据核查文件中；影响提交的未决事项另行告知用户。Agent/具备文件生成能力的环境完成全文时，必须另交独立的逐段引用原文对照与证据核查文件，遵循下文规范。若用户只需要某一步，交付相应部分，不重复输出已接受的内容。可使用 `scripts/check_manuscript.py` 对 Markdown/纯文本稿机械检查顺序编码和字数（不是学术证据验证）。

## 正式综述与独立证据核查交付（v1.6）

- Agent 模式或其他具有文件生成能力的环境完成全文时，默认必须额外生成一个独立的可下载核查文件，优先自包含 HTML（可离线查看正文对照、可在线打开参考文献链接），用户指定时可选择 DOCX、Markdown 或其他适当格式。不得仅在聊天中声称核查完毕或只提供参考文献总表。若当前环境不能生成文件，说明限制并给出结构化替代内容。无需为此再次询问用户。
- 逐段核对最终稿，包含引言、主体、结论、摘要（如有引文）及图表说明中实际使用的引用。每个正文段落分配稳定 ID，展示完整最终稿段落、段内具体论断和对应的最终引用编号；多条引用或多个独立事实逐项对照，不能用一条引文笼统支撑整段。纯过渡、作者综合观点及未引用段落也登记并区分，不强行添加引文。
- 每条证据记录原文中支持该论断的必要短引（在来源许可、安全和版权允许范围内准确引用，不为凑全而复制大量原文；不适宜引用时给出安全的证据释义与可核实定位，注明原因）、中文释义、原文真实位置（页码/章节/段落/图表等，以实际可见为准）、核查深度 A/B/C/D、匹配程度、局限和必要修改建议。不得捏造引文、页码或将模型改写伪装成原文。仅摘要可访问时明确标为摘要证据；未取到全文或不能确认支持关系则标“待核查”，不冒称核查通过。
- 仅在独立证据核查文件中为每条参考文献使用最终编号并附实际核实的 DOI 链接（https://doi.org/...）或稳定期刊/数据库入口，条件允许时补充 PubMed、PMCID、合法全文链接；不把 DOI 入口称为免费全文。正文引用、核查文件及书目统一映射，链接未知则标明，不编造。记录核查范围、访问日期、来源版本、覆盖率、未核实项与修订历史。
- 参照 `references/evidence-audit.md` 和 `references/style-and-delivery.md`。写每节时就保存证据账本，最后按终稿汇总并检查文件确实生成、能打开、引用对应无遗漏且所有链接是实际已核实来源。不得将证据文件变为文献全文汇编、受限内容转载或高风险生物操作细节汇编；不擅自上传用户文稿/文献至公开仓库。确认节点、学术诚信、安全及版权约束不变。

## 可编辑科研配图（按需启用）

- 流程图、概念性技术路线图、机制图、图形摘要或定量证据图按 `references/scientific-figures.md` 执行。先明确图的科学目的和证据来源；定量图须先确认数值能否取得。如配图仅为建议，先向用户提出建议，不擅自增加图。
- **配色选择为绘图前的必要确认环节**：读取 `references/color-palettes.md` 和 `references/color-palettes.json`（相对于 Skill 根目录），从19组参考色卡及既有自定义配色中按图件内容挑选3–5组。必须向用户实际展示色块预览、编号（P01–P19，不显示或另拟色卡名称）、HEX及每组适用理由（可用客户端色块、SVG/HTML色卡或已验证可访问的预览文件），提供“自定义配色”“由AI自行搭配”选项。询问用户希望的配色/风格及输出格式；若尚未确认且未授权代选，先等待选定再制作正式图。已指定或此前确认的配色直接沿用；用户无想法、授权代选或明确要求直接完成时，自选并说明方案，不重复询问。整篇综述应保持颜色语义一致；不能只列编号、不提供实际颜色，也不能因参考图包含渐变或3D而违反白底、纯色平涂、独立可编辑对象的规则。
- 默认白底、扁平2D矢量、无渐变阴影或3D渲染、简约少框；同类对象颜色、形状、尺寸、比例、线宽和细节一致；重复小元素分别绘制为可独立编辑对象，不合并轮廓。Blender 风格仅指专业、精细统一的插画感。
- 优先实际交付独立矢量图元的 SVG、原生可编辑形状的 PPTX、适合插入的预览及图注。需要 AI/PSD 时先检查本地软件与权限，能调用则实际调用；不能调用时提供可编辑中间格式，并在确有必要时引导使用具备本地访问权限的 Codex 或受支持的 Work 环境。不得将普通图片声称为可编辑源文件，或声称已调用未经验证的软件。
- 图的科学准确性、证据边界、科研伦理、版权和安全要求与正文一致。不得用机制图或路线图替代高风险生物工程的操作、构建、优化或传播指导。交付前检查对象独立性、视觉效果及文件兼容性，明确未能验证的事项。

## 固定写作偏好

- 以研究对象、科学问题或已有发现为段落主语；用内容间的因果、比较、递进关系承接下一段。
- 减少“在……方面”“除……之外”“具有重要意义”“提供了新思路”“进一步拓展了”等无实质内容的套话，但不机械禁用必要连接词。
- 事实有引用，分析有依据，观点有逻辑；用适当限定词体现证据强度，不要求每句分析都出现“本文认为”。
- 文献方法重在说明证据是什么，不复制方法步骤或不必要的操作细节；写明研究设计、对象、终点、关键结果及适用范围（在合适且安全的前提下）。
- 不把相关性当一致性或因果性；不把缺乏统计显著性等同于没有效果；不把动物或早期临床结果外推为确证临床获益。
- 参考文献默认采用顺序编码制、GB/T 7714 格式（以学校或期刊要求的具体版本为准），正式综述书目采用普通文本著录，默认不添加可点击超链接或额外核查入口；若引用规范本身要求 DOI 或 URL，则保留必需的普通文本著录字段，不新增超链接。独立证据核查文件必须提供已核实的可点击 DOI 或稳定来源入口；缺失时在核查文件中标注未核实。未核实影响因子、引用次数及分区不得填猜测值。
